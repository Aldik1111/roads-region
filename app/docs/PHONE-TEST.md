# Android Chrome: тест рядом с ПК

Это запуск в локальной Wi-Fi-сети. На телефоне используйте адрес, напечатанный командой запуска; `localhost` на телефоне означает сам телефон. ПК должен оставаться включённым. Используются существующие база, фото и демонстрационные роли приложения: созданные с телефона записи видны на ПК.

## Запуск на Windows

Из корня приложения:

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools/phone-requirements.txt
.\start-phone-test.ps1 -Build
# Если физических сетевых подключений несколько:
.\start-phone-test.ps1 -Address 192.168.1.108
```

По умолчанию HTTPS — порт 8443, страница установки — HTTP 8444. Выбирается физический адаптер с шлюзом; VPN и виртуальные адаптеры автоматически не выбираются. Сервер привязан к одному локальному IPv4, не ко всем интерфейсам. Скрипт печатает адреса и SHA-256 публичного сертификата.

Разрешение брандмауэра — один раз в **PowerShell от имени администратора**, с адресом из вывода запуска:

```powershell
.\phone-firewall.ps1 -Address 192.168.1.108
```

Правило разрешает только TCP 8443/8444 на выбранном адресе и физическом интерфейсе, только из `LocalSubnet`. Профиль сети и другие правила не меняются. При собственных портах передайте одинаковые `-HttpsPort` и `-SetupPort` обеим командам.

## На Android

1. Подключите телефон к той же Wi-Fi-сети, что и ПК. Откройте напечатанный **HTTP-адрес установки** или отсканируйте QR-код со страницы установки на ПК.
2. Скачайте `roads-phone-ca.crt`. Сверьте SHA-256 в свойствах сертификата с отпечатком на ПК.
3. В настройках Android найдите «Установка сертификатов» → **Сертификат ЦС / CA**, выберите этот файл. Раздел часто находится в «Безопасность и конфиденциальность → Дополнительные настройки → Шифрование и учётные данные». Названия зависят от производителя; это не сертификат Wi-Fi. Android может потребовать PIN-код и показать предупреждение о новом центре доверия.
4. Вернитесь на страницу установки и нажмите **«Проверить соединение и GPS»**. В Chrome не должно быть предупреждения о недоверенном сертификате. Если оно есть, проверьте установленный сертификат, адрес и дату устройства; переход с игнорированием предупреждения не заменяет доверенный HTTPS.
5. На диагностике нажмите «Проверить геопозицию» и разрешите доступ. Должны появиться позиция, время и точность. Эта страница не отправляет координаты на сервер.
6. Нажмите «Открыть приложение», выберите инспектора и войдите. Разрешите геолокацию Chrome также на уровне Android, если система запросит.

Тестовый корневой сертификат добавляет доверие на телефоне. Установите только файл с этого ПК. После теста удалите **только «Roads Phone Test Local CA»** в пользовательских доверенных сертификатах. Не нажимайте «Очистить все учётные данные».

Справочные материалы: [требования Geolocation API к защищённому контексту](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API), [управление сертификатами Android](https://support.google.com/pixelphone/answer/2844832?hl=ru). Экран установки CA у конкретного производителя может отличаться от примера Google для Wi-Fi-сертификатов.

## Короткая проверка

- Назначить маршрут с ПК; открыть его на телефоне и начать осмотр при связи.
- Сделать фото дефекта, дождаться «Сохранено на устройстве», перезагрузить и продолжить черновик.
- Отключить Wi-Fi на телефоне: локальный сервер станет недоступен даже при мобильном интернете. Зафиксировать дефект с актуальной позицией; вернуть Wi-Fi и проверить отправку очереди и единственную запись на ПК.
- Проверить сдачу подрядчиком и приёмку инспектором с контрольным фото.

Держите страницу видимой и экран включённым. Фоновая запись GPS и карта без сети не реализованы. Черновики в `http://localhost:8000` на ПК и в HTTPS-адресе телефона — разные хранилища браузера; серверные записи общие. При смене адреса ПК локальные черновики остаются у старого адреса: отправьте очередь до перевыпуска/смены сети, если это возможно.

## Если не открывается

- Страница установки не отвечает: проверить Wi-Fi, адрес ПК, правило Windows, отсутствие гостевой сети/изоляции клиентов. VPN на ПК/телефоне может менять маршруты.
- HTTPS не доверен: проверить тип CA, файл сертификата, IP и часы. Не отключать проверку сертификатов в Chrome.
- GPS недоступен: включить местоположение Android и разрешить точное местоположение для Chrome и сайта. При отсутствии позиции проверить устройство на открытом воздухе.
- После смены IP или истечения сертификата остановить тест и выполнить `start-phone-test.ps1 -Address НОВЫЙ_IP -RenewCertificate`; установить новый CA на телефоне и обновить правило брандмауэра. Старый CA удалить. Сертификат сервера действует 14 дней, CA — 30 дней; закрытый ключ CA не хранится.

## Остановка и проверки

```powershell
.\stop-phone-test.ps1
# В PowerShell администратора, когда тест завершён:
.\phone-firewall.ps1 -Remove
# Проверка TLS с верификацией цепочки и имени, без отключения проверки:
.\.venv\Scripts\python.exe tools/phone_test.py check --ip 192.168.1.108
.\.venv\Scripts\python.exe -m pytest tools/test_phone_test.py backend/test_api.py -q
# Требуются Chrome, Playwright и запущенный тестовый HTTPS:
node frontend/tests/phone-test-browser.cjs
```

Секреты и сертификаты находятся в игнорируемой Git папке `.phone-test/`; закрытый серверный ключ доступен только текущему Windows-пользователю и SYSTEM. HTTP-сервер установки отдаёт только страницу, QR и публичный CA. Команда остановки оставляет `localhost:8000` и данные приложения на месте.

# Доступ к проверке работ — 9 октября 2026

## Причина

На ПК единственная прямая кнопка проверки находилась под списком маршрутов. На телефоне использовалась нижняя навигация. В открытом списке не было отдельного обновления для новых отчётов из другого кабинета.

Также исходная демо-запись № ДЕМО-004 создавалась со статусом `review`, но без отчёта ремонта. Попытка принять или вернуть такую запись приводила к обращению к несуществующей попытке ремонта.

## Изменения

- На ПК сверху доступны «Маршруты», «Мои дефекты», «Проверка работ» со счётчиком. Переход к проверке сбрасывает фильтр отдельного маршрута.
- На телефоне нижний пункт называется «Проверка работ» и показывает число ожидающих отчётов.
- Заголовок раздела — «Проверка работ». Кнопка «Обновить» запрашивает свежий список с сервера. Пустая очередь отображается явно.
- У существующей записи без отчёта показано объяснение; кнопки приёмки недоступны. API возвращает понятный `409 MISSING_REPAIR_REPORT`, не изменяя карточку.
- При создании новой демонстрационной БД пример проверки получает явно обозначенный демонстрационный отчёт с иллюстрацией. Существующая БД и пользовательские отчёты не переписывались.

## Проверки

- `npm run build`: успешно, остаётся предупреждение о размере JS-бандла.
- `.venv/Scripts/python.exe -m pytest backend -q`: **22 passed**, включая полный цикл сдачи → доработки → повторной сдачи → приёмки, а также отсутствие отчёта и корректность новой демо-записи.
- `node frontend/tests/inspector-review-browser.cjs`: Chrome, 1440 и 390 px. Проверены видимость пункта без прокрутки, пустая очередь, появление отчёта через обновление, обязательное замечание при возврате, приёмка, исчезновение рассмотренного отчёта из очереди, карточка без отчёта. **0 ошибок JavaScript**. API подменён, пользовательские записи не меняются. Нужны Chrome, работающий локальный сервер и Playwright (`PLAYWRIGHT_MODULE` при внешней установке); `APP_URL` переопределяет адрес.

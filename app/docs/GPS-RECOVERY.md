# Восстановление GPS — 9 октября 2026

## Поведение

- При первом входе инспектор ждёт реальную актуальную позицию. Разрешение браузера само по себе не открывает кабинет.
- После успешного определения позиции временный отказ источника начинает 60 секунд переподключения. При отсутствии новых callback позиция считается устаревшей через 30 секунд; затем начинается тот же период восстановления.
- Первые 15 секунд переподключения нет уведомления. Затем появляется спокойная полоса со временем ожидания. Она не перехватывает фокус и не закрывает форму.
- Во время восстановления можно редактировать форму, выбирать точку на карте, добавлять фото и завершать текущий осмотр. Начало нового осмотра и отправка нового дефекта ждут свежей позиции.
- Старые координаты не выдаются за текущие и не добавляются в GPS-трек. Координата уже открытого сообщения сохраняется как точка обнаружения, включая ручную отметку.
- Повторные ошибки и ручной повтор не продлевают срок. После истечения срока работа блокируется до новой позиции; форма и фото остаются в памяти открытой страницы.
- Явный отзыв разрешения страницы блокирует работу сразу. Разрешённый сайту, но временно недоступный системный источник получает период восстановления, если ранее была позиция.
- Возврат GPS автоматически убирает уведомление или блокировку. Обновление страницы всё ещё может потерять незавершённую форму: постоянное локальное хранение пока не реализовано.

## Трассы и отсутствие мобильной сети

Спутниковый GPS/GNSS телефона может определять координаты вне покрытия мобильной сети при достаточном обзоре неба. Тоннели, препятствия и характеристики устройства влияют на сигнал. Web Geolocation выбирает доступный источник устройства; приложение не может доказать, что координата получена исключительно от спутников. ПК без спутникового приёмника обычно зависит от иных источников.

В нынешнем MVP карты, построение маршрута и серверные операции используют сеть. Неотправленные точки удерживаются только в памяти страницы, фоновые вкладки приостанавливают наблюдение. Это не гарантирует запись поездки без связи или при блокировке экрана.

### Следующий этап, ещё не реализован

1. Заранее загружать назначенный маршрут и разрешённую для офлайн-использования карту региона. Нельзя массово скачивать публичные тайлы OSM в обход правил сервиса.
2. Хранить трек, черновики дефектов и оригиналы фото в постоянной локальной очереди (IndexedDB для PWA либо SQLite/файлы для мобильного приложения).
3. Синхронизировать очередь после восстановления сети, с идемпотентными идентификаторами, подтверждением сервера и сохранением исходного времени/точности каждой позиции.
4. Для непрерывной записи при заблокированном экране использовать мобильное приложение с системным фоновым отслеживанием и необходимыми разрешениями. Обычная вкладка браузера этого не гарантирует.
5. Проверять на реальном телефоне: маршрут между городами, отключение мобильных данных, потеря GPS, блокировка экрана, перезапуск приложения и повторная синхронизация без дублей.

Источники: [устройство GPS](https://www.gps.gov/systems/gps/index.php), [точность и препятствия](https://www.gps.gov/gps-accuracy), [Web Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API), [Android background location](https://developer.android.com/develop/sensors-and-location/location/background).

## Проверка реализации

- `cd frontend; npm run build` — TypeScript/Vite успешно. Предупреждение о размере JS-бандла остаётся.
- `npm run test:gps` — 17 групп проверок: первый вход, ошибки источника, стационарное обновление, 15/60 секунд, повтор без продления, устаревшие callback, мутации в период восстановления, скрытие окна и отзыв разрешения.
- `node frontend/tests/gps-grace-browser.cjs` — Chrome, 1440 и 390 пикселей: трёхсекундный обрыв без уведомления, загрузка фото во время восстановления, уведомление после 15 секунд, блокировка после минуты, сохранение текста/фото и возврат доступа. Новые точки в треке отсутствуют до нового callback. Ошибок JS нет.
- Для браузерного сценария нужен запущенный локальный сервер и модуль Playwright (доступный как `playwright` либо через `PLAYWRIGHT_MODULE` с путём к установленному модулю), установленный Chrome. `APP_URL` меняет адрес; `GPS_SCREENSHOTS` задаёт существующую папку снимков. API и координаты в этом тесте подменяются: пользовательские записи не создаются.
- Проверки выполнялись с управляемыми сигналами геолокации. Реальная поездка, спутниковый приём телефона, офлайн-режим и работа при заблокированном экране этими тестами не подтверждены.

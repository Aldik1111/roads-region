# План локального теста Android — 2026-10-10

## Согласованный результат

Пользователь выбрал тест Android/Chrome рядом с ПК в одной Wi-Fi-сети. Нужны локальный HTTPS, доверие сертификату, страница диагностики и работа существующего приложения с телефона. Публичный хостинг, новые аккаунты и перенос базы отложены за пределы этого этапа.

## Реализация

- [x] Локальный помощник создаёт CA и сертификат с SAN для выбранного IPv4; закрытый ключ CA не сохраняется. Секреты исключены из Git и HTTP-раздачи. При смене IP/истечении сертификата требуется явный перевыпуск.
- [x] Отдельный процесс обслуживает приложение по HTTPS и только три публичных ресурса установки по HTTP. Данные и роли существующего приложения сохраняются. Обычный localhost:8000 продолжает работать.
- [x] PowerShell-команды запуска и остановки проверяют адрес, занятые порты и принадлежность процесса. Отдельная команда брандмауэра ограничена физическим интерфейсом, адресом ПК, двумя TCP-портами и LocalSubnet.
- [x] Защищённая сессионная cookie при HTTPS; локальный HTTP-вход продолжает работать.
- [x] Диагностика Android без внешних ресурсов: сервер, secure context, поддержка API, однократная позиция по нажатию. Координаты не отправляются.
- [x] Service worker не подменяет офлайн-оболочку диагностической страницей.

## Проверки

Тесты: цепочка сертификата/SAN, повторное использование, явная смена IP, запрещённые адреса, закрытый ключ недоступен по HTTP; HTTPS-cookie и выход; браузер 390 px с управляемой геопозицией; сохранность офлайн-оболочки после перехода на диагностику. Затем проверка настоящего телефона самим пользователем: установка CA, открытие без предупреждения, запрос GPS, вход и фото.

## Границы

Компьютер и телефон остаются в одной сети, ПК включён. Для установки правила Windows требуются административные права; для установки CA на Android — действие владельца телефона. Локальный CA удаляется с телефона после теста. Изоляция Wi-Fi-клиентов и фактическое разрешение GPS проверяются только с настоящего устройства.

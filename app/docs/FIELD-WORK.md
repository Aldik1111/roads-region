# Полевая работа без связи и приёмка ремонта

## Как пользоваться

1. Перед выездом откройте приложение при наличии сети, войдите как инспектор и дождитесь загрузки назначений и сообщения о доступности приложения без сети. Начните нужный осмотр.
2. В форме дефекта текст, координаты и выбранные фотографии сохраняются в IndexedDB этого устройства. Дождитесь надписи «Сохранено на устройстве». После перезагрузки нажмите «Продолжить черновик».
3. «Отправить сообщение» фиксирует неизменяемую операцию в локальной очереди. Без сети она остаётся на устройстве; карточка очереди не выдаётся за принятую сервером запись.
4. Актуальные GPS-точки сохраняются локально. «Завершить» добавляет завершение после уже записанных точек и сообщений. После перезагрузки такой осмотр не возобновляет запись.
5. При связи и доступном GPS очередь отправляется автоматически в открытой видимой вкладке. Есть ручная кнопка «Отправить очередь». Фото отправляются до связанного дефекта. Потерянный ответ повторяется с прежним ключом; подтверждение сохраняется перед удалением операции из очереди.
6. Новый осмотр начинается при связи и после отправки предыдущей очереди. Если сеанс истёк или сменился пользователь, данные сохраняются до входа в нужную учётную запись.

## Приёмка

В разделе «Проверка работ» инспектор сравнивает исходные фотографии и последний отчёт подрядчика, добавляет контрольное фото и подтверждает три пункта: покрытие восстановлено, видимых повреждений нет, участок безопасен. Для приёмки необходимы свежая GPS-позиция и сеть. Отказ требует замечания, фото и чек-лист для отказа необязательны.

Сервер проверяет роль, владельца контрольных фотографий, все пункты чек-листа, диапазоны координат и возраст позиции. Время позиции допускается не старше пяти минут; интерфейс требует свежесть по текущим правилам GPS. Сохраняются материалы, время, координаты, точность и расстояние до дефекта. Они отображаются в истории инспектора, диспетчера и подрядчика. Расстояние не блокирует решение; сведения GPS и загруженное фото сами по себе не доказывают физическое присутствие или момент съёмки.

## Границы этой версии

- Офлайн-режим относится к уже загруженным назначениям и начатому осмотру инспектора. Первый вход и начало нового осмотра требуют сети.
- Сохраняется оболочка приложения и геометрия маршрута. Полная офлайн-карта, построение новых маршрутов без сети и фоновая запись при заблокированном экране не реализованы.
- Черновик дефекта один на пользователя и устройство. Новая фиксация предлагает продолжить существующий черновик; удалить его можно явно. Отправленных сообщений в очереди может быть несколько.
- Черновики и очередь хранятся в браузере. Очистка данных сайта, приватный режим или удаление профиля могут их уничтожить. Ошибка записи/нехватка места отображается; несохранённые точки вызывают предупреждение перед выходом. Подтверждённые оригиналы пока удерживаются локально для безопасного восстановления; автоматическая очистка архива — отдельное улучшение.
- Контрольные фото приёмки и отчёт подрядчика пока отправляются при связи. Автосохранение полевого черновика не означает автосохранение всех форм приложения.
- Ошибки проверки сервером не удаляют очередь и не превращаются в успешную отправку. При изменении назначения или закрытии осмотра другим пользователем потребуется разрешить конфликт.
- Фото, координаты и подтверждения разделены по владельцу локально. При каждой отправке проверяется серверный сеанс и заголовок владельца очереди; локальное сохранение не заменяет серверную авторизацию.

## Проверка

- API: `python -m pytest backend -q` — 28 тестов, включая идемпотентность загрузки фото, потерянный ответ дефекта после завершения осмотра, материалы приёмки, чужие фото и смену владельца сеанса.
- `cd frontend; npm run test:gps` — 19 групп проверок прежнего GPS-поведения.
- `node frontend/tests/field-work-browser.cjs` — собранное приложение, service worker, отключение сети, перезагрузка и восстановление текста/фото, очередь, завершение, потерянный ответ и один серверный дефект после двух запросов.
- `npm run test:field-queue` из frontend — отдельный временный Vite, реальный IndexedDB, порядок записи, изоляция пользователей, повтор с прежним ключом, сохранение фото, локальная запись во время зависшей сетевой отправки.
- `node frontend/tests/inspector-review-browser.cjs` — приёмка и доработка на 1440/390 px, контрольное фото, все пункты чек-листа, GPS и сохранённые материалы.
- Браузерным сценариям нужен установленный Chrome и Playwright. Путь к внешнему модулю задаётся через `PLAYWRIGHT_MODULE`; для сценариев собранного приложения `APP_URL` по умолчанию `http://127.0.0.1:8000`. Тесты перехватывают API, пользовательские записи не создаются. GPS управляемый; настоящая поездка и работа спутникового приёмника телефона ещё требуют полевого испытания.

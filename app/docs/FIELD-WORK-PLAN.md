# Надёжная полевая работа и приёмка

## Согласованная цель

После предложения этапов «автосохранение → офлайн-очередь → полноценная приёмка» пользователь поручил начать реализацию. Сохраняем визуальный стиль и GPS-правила. Root интегрирует, существующие субагенты Luna реализуют независимые части.

## Решения

- IndexedDB хранит черновик, оригиналы выбранных фото, снимок назначенных маршрутов и очередь отдельно по пользователю. Ошибка записи явно отображается; неподтверждённые данные не называются сохранёнными.
- Осмотр начинают при связи, перед выездом. Уже начатый осмотр и загруженные назначения доступны после перезапуска без сети. GPS по-прежнему обязателен; координаты не подменяются.
- Полевая отправка сначала фиксируется локально, затем передаётся серверу. Очередь: исходные фото → дефект; точки и завершение осмотра сохраняют порядок. Идентификаторы запросов и GPS-точек сохраняются при повторе.
- Перед синхронизацией сервер подтверждает текущего пользователя. Ошибка авторизации или валидации не удаляет локальные данные. В интерфейсе видны очередь, ошибка и повтор.
- Service worker сохраняет оболочку приложения. Карта без сети может не иметь подложки; загруженная геометрия маршрута остаётся. Офлайн-тайлы и фоновая запись при заблокированном экране — отдельный этап.
- Приёмка требует контрольного фото, трёх пунктов чек-листа, актуальных GPS-координат. Отказ требует замечания. В карточке сохраняются материалы и место проверки; расстояние информирует, но не блокирует приёмку.

## Задачи

1. Субагент inspector: fieldStorage.ts, fieldQueue.ts, локальные фото в PhotoUpload; тесты сохранения, повторов и изоляции пользователей.
2. Субагент backend: идемпотентные фото, валидация/хранение доказательств приёмки, время завершения из офлайн-очереди, ранний повтор идемпотентного дефекта; изолированные API-тесты.
3. Субагент operations: RepairReview и просмотр результата приёмки, адаптация ПК/телефон.
4. Root: черновик и восстановление Inspector, снимок назначений, очередь точек/дефектов/завершения, индикаторы отправки, восстановление сеанса и оболочки без сети, сборка и браузерная проверка.

## Проверки рисков

- Потеря сети после успешного приёма запроса сервером: повтор возвращает прежнюю запись, не создаёт дубликат.
- Перезагрузка без сети: черновик, фото и ожидающие точки остаются; виден реальный статус синхронизации.
- Вход другого пользователя: чужие данные и задания не синхронизируются.
- Заполненное/недоступное хранилище: понятная ошибка, отсутствие ложного сообщения об автосохранении.
- Плохой GPS или неполный чек-лист: приёмка недоступна; сервер также проверяет входные данные.

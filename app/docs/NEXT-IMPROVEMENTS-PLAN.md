# Улучшения полевой работы — 2026-10-10

Пользователь поручил выполнить список улучшений нескольким GPT-6 Luna субагентам; ведущий агент интегрирует и проверяет. Сохраняются дизайн, данные, обязательная геолокация и локальный Android HTTPS. Установка внешнего хостинга не выбрана: последнее предпочтение — тест рядом с ПК.

## Задачи и владельцы

- Карта/маршруты: состояния загрузки, задержки, ошибки и сети; повтор; сохранение вида; конфигурируемый провайдер; консервативный прогресс и пропуски GPS. Агент map_improvements владеет компонентами карты и новым RouteProgress.
- Очередь: видимые операции/подтверждения, исправление только однозначно отклонённых сообщений с новым ключом и сохранением порядка, объём хранения и безопасная очистка отправленных фото. Агент queue_improvements владеет очередью/хранилищем/панелью.
- Сервер: версия и изменение маршрута вне активного осмотра, уведомления внутри кабинета, срок проверки ремонта, отчёт подрядчиков, отключаемое демо. Агент backend_improvements владеет API/тестами.
- Ведущий: интеграция панелей, просмотр фото с увеличением, личный вход без демо-подстановки, инструменты создания учётных записей и резервного копирования/восстановления, конфигурация HTTPS-размещения, проверка и публикация исходников.

## Правила

1. Потерянный ответ сервера не разрешает изменять запрос: это может создать дубликат. Корректируются только подтверждённые ошибки проверки полей; очередь не теряется.
2. Очистка не затрагивает фото черновиков или ожидающих операций. Хранение разделено по пользователям.
3. Пройденный GPS-путь — оценка покрытия, не доказательство осмотра. Пропуски не соединяются как пройденные участки.
4. Переназначение активного маршрута блокируется. Результаты прошлых осмотров сохраняют автора.
5. Уведомления остаются в приложении; внешние сообщения и push без дополнительной настройки не отправляются.
6. Публичный OSM не используется для массового скачивания офлайн-карт. Другой провайдер выбирается после замеров и согласования необходимых условий/ключей.
7. Восстановление резервной копии проверяется в отдельной пустой папке. Рабочая база не заменяется.

## Проверки

Изолированные API-тесты ролей/версий/сроков, тесты потерянного ответа и исправления очереди, безопасная очистка, геометрия прогресса, браузерные сценарии ошибок тайлов/повтора/сохранения вида, адаптивность 390/1440, сборка. Проверка резервной копии включает хэши и целостность SQLite после восстановления. При недоступном Docker сборка контейнера отмечается непроверенной.

### Зависимости следующего этапа

Публичное размещение требует выбранного хостинга/домена. Полевую поездку проверяет пользователь на настоящем Android. Офлайн-карты требуют источника с соответствующей лицензией; запись при заблокированном экране требует отдельно спроектированного Android-клиента/foreground service. Эти зависимости фиксируются явно и не выдаются за готовые функции браузера.

# Дороги области — рабочий MVP

Локальное приложение: **http://localhost:8000**. Исходный дизайн сохранён без изменений в `design/reference.html`. Интерфейс использует его тёплый светлый фон, тёмно-зелёную навигацию, бирюзовые действия и пастельные статусы.

## Что работает

- **Полевая работа:** автосохранение черновика дефекта и оригиналов фото на устройстве, восстановление после перезагрузки, очередь точек/сообщений/завершения при потере сети и отправка без дублей. Начните осмотр при связи перед выездом. [Инструкция и ограничения](docs/FIELD-WORK.md).
- **Новые улучшения:** состояния загрузки карты и сохранение вида, оценка покрытия маршрута, подробная очередь с исправлением отклонённых сообщений, безопасная очистка локальных фото, переназначение маршрутов, уведомления, сроки проверки, отчёт подрядчиков и увеличение фото. [Итоги и проверки](docs/IMPROVEMENTS-2026-10-10.md).
- **Приёмка ремонта:** сравнение «До / После», контрольное фото инспектора, обязательный чек-лист, координаты и точность GPS, сохранённые материалы проверки для всех ролей.

- Диспетчер, раздел **«Маршруты»**: ставит начало и конец на карте; один найденный автомобильный вариант выбирается автоматически, несколько вариантов требуют выбора. Цветные линии и метки расхождения помогают сравнить пути. Затем задаёт название, выбирает инспектора и сохраняет назначение.
- Инспектор, **«Мои маршруты»**: видит свои назначения, выбирает маршрут и начинает осмотр. Одновременно активен один маршрут. Осмотры, GPS-путь и найденные дефекты сохраняются; диспетчер видит их в результатах маршрута.
- Инспектор: запись GPS в открытой вкладке, ручная точка дефекта, фото и описание, уточнение, приёмка и доработка, повторный дефект после закрытия.
- GPS обязателен для работы инспектора. После краткого сбоя даётся 60 секунд на восстановление; первые 15 секунд без уведомления. Форма и фото доступны, новый осмотр и отправка дефекта ждут свежей позиции. После минуты без сигнала кабинет блокируется, введённые данные остаются в открытой форме. Явный отзыв разрешения блокирует работу сразу. [Поведение, проверки и план работы на трассах](docs/GPS-RECOVERY.md). Рабочая карта открывается на текущем месте, выбранная точка отмечается маркером. Масштабирование — колёсиком мыши и двумя пальцами.
- Диспетчер: список, карта, поиск и статусы, назначение, смена исполнителя и срока с причиной, запрос сведений, сравнение и связывание дубликатов, отмена.
- Подрядчик: только свои назначения, принятие и начало работ, фотоотчёт, повторная сдача после доработки.
- Оригиналы фотографий, история действий, отдельные попытки ремонта, проверка ролей на сервере, контроль версии записи и повторных отправок.
- ПК: несколько рабочих колонок; планшет: компактная компоновка; телефон: переключаемые панели и нижняя навигация инспектора. Снимки экранов находятся в `docs/screenshots`, галерея — `docs/GALLERY.html`.

## Запуск в этой папке

**Тест с Android по Wi-Fi:** [инструкция HTTPS, сертификата и подключения телефона](docs/PHONE-TEST.md). Команда `start-phone-test.ps1` запускает отдельный локальный HTTPS-адрес и страницу подключения с QR-кодом; `localhost:8000` остаётся доступным на ПК.

```powershell
.\start-local.ps1
# После изменения frontend:
.\stop-local.ps1
.\start-local.ps1 -Build
# Остановка:
.\stop-local.ps1
```

Сервер запускается скрытым процессом, логи находятся в `logs/`. SQLite хранится в `backend/roads.db`, загруженные оригиналы — в `backend/uploads/`. Эти локальные данные исключены из Git. Проверяемая резервная копия и восстановление описаны в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

На новом компьютере нужны Python 3.12+ и Node.js 22+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Set-Location frontend
npm ci
npm run build
Set-Location ..
.\start-local.ps1
```

Разработка с обновлением интерфейса: сервер на порту 8000 и `npm run dev` из `frontend` на 5173. Vite проксирует `/api` на сервер.

## Построение маршрутов

Поставьте на карте точки **А** и **Б**. Для точного ввода раскройте координаты. После изменения любой точки варианты рассчитываются заново, предыдущий выбор сбрасывается. При нескольких вариантах выберите цветную линию либо карточку с расстоянием и временем, затем нажмите «Сохранить маршрут и назначить».

Маршрутизатор использует [OSRM Route API](https://project-osrm.org/docs/v5.24.0/api/#route-service) с автомобильным профилем и альтернативами. Он возвращает разумные варианты и не гарантирует перечисления всех возможных путей. Надпись «Найден один вариант» означает один результат сервиса. Расчётное время не включает осмотр и остановки. Точки привязываются к дороге в пределах 500 м; ошибка сервиса не создаёт маршрут.

Для расчёта нужен интернет. Координаты двух точек отправляются на публичный `https://router.project-osrm.org`; для своего OSRM задайте переменную окружения `ROUTING_BASE_URL`. Предпросмотр сохраняется на сервере на 60 минут, выбранная геометрия остаётся в базе после назначения. Назначение, название и примечание маршрута можно изменить вне активного осмотра. Смена версии защищает от одновременных изменений; удаление маршрута не добавлено. Старый R-01 сохранён как демонстрационный маршрут.

## Стек и PostgreSQL

React 19, TypeScript, Vite, Leaflet, FastAPI, SQLAlchemy. В текущем запуске используется **SQLite**: движок Docker на компьютере недоступен. PostgreSQL поддерживается кодом, но в этой сессии не запускался и не тестировался.

Для PostgreSQL: скопируйте `.env.example` в `.env`, задайте пароль, запустите `docker compose up -d`. Перед запуском сервера установите `$env:DATABASE_URL='postgresql+psycopg://roads:ВАШ_ПАРОЛЬ@localhost:5432/roads'`. Пароль в URL должен быть URL-кодирован. Существующие SQLite-данные автоматически не переносятся; новая база получит демо-записи.

## Проверки и границы MVP

```powershell
.\.venv\Scripts\python.exe -m pytest backend/test_api.py -q
Set-Location frontend
npm run build
```

Подробные результаты — `docs/VERIFICATION.md`, `docs/ROUTES-VERIFICATION.md`, `docs/GPS-VERIFICATION.md`, `docs/FIXES-2026-10-09.md`, `docs/FIELD-WORK.md`, `docs/PHONE-TEST.md`. Актуальные результаты новых проверок — в [отчёте улучшений](docs/IMPROVEMENTS-2026-10-10.md); прежние отчёты отражают состояние на свою дату. Новые экраны маршрутов — `docs/ROUTES-GALLERY.html`. GPS и жесты проверены эмуляцией браузера; поездка с реальным телефоном не проводилась. На localhost геолокация доступна, для доступа с телефона по сети нужен HTTPS. Обычный сервер слушает только этот компьютер; отдельный тест телефона запускается по инструкции выше.

GPS записывается при видимой вкладке. При скрытии вкладки/блокировке телефона запись может прерываться; интервалы более минуты отмечаются на карте. Точки, сообщения и завершение сохраняются в локальной очереди; неподтверждённые записи отправляются при восстановлении связи. При ошибке локального сохранения показывается предупреждение. Карта OpenStreetMap и шрифт требуют интернет; при недоступной подложке геометрия и точки остаются. Новый осмотр начинается при связи; подробные границы — в `docs/FIELD-WORK.md`.

Это локальный MVP. Подготовлены конфигурация публичного HTTPS, отключение демо, управление личными пользователями и проверяемые копии SQLite: [инструкция размещения](docs/DEPLOYMENT.md). Публичное размещение, проверка PostgreSQL, перенос данных и резервное копирование production требуют отдельного завершения. Регистрация пользователей, push-уведомления и фоновая GPS-запись в этот этап не входят.

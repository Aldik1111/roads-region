# Дороги области

Обследование дорог, фиксация дефектов с координатами и контроль ремонта до независимой приёмки.

**Код задачи GTON:** А-3. **Статус репозитория:** реализован локальный MVP с кабинетами инспектора, диспетчера и подрядчика. Код и сохранённый дизайн находятся в [`app/`](app/).

Инструкция установки и запуска: [app/README.md](app/README.md). Стек: React, TypeScript, Vite, Leaflet, FastAPI и SQLAlchemy. Локально используется SQLite; конфигурация PostgreSQL приложена.

## Маршруты и GPS

Диспетчер задаёт A/B, выбирает один из предложенных путей и назначает инспектору. Инспектор выбирает маршрут из своих назначений. Работа инспектора требует актуальной геолокации; карты открываются на текущем месте и поддерживают колёсико и жест двумя пальцами.

## С чего начать
1. Прочитать [полное описание и ТЗ](docs/SPECIFICATION.md).
2. Выбрать одну из трёх инструкций ниже.
3. Согласовать контракт и начать общий сквозной сценарий в первый день.
4. При смене роли заполнить [передачу работы](docs/HANDOFF.md).

| Роль в команде | Зона ответственности | Подробная инструкция |
|---|---|---|
| Участник 1 | Мобильный кабинет инспектора | [Задачи участника 1](participants/PARTICIPANT_1.md) |
| Участник 2 | Сервер, данные и правила процесса | [Задачи участника 2](participants/PARTICIPANT_2.md) |
| Участник 3 | Кабинеты диспетчера и подрядчика | [Задачи участника 3](participants/PARTICIPANT_3.md) |

Номера обозначают обязанности, а не людей. Ролями можно меняться. Имена и личные назначения здесь не фиксируются.

## Организация
Владелец актуальности контракта данных — **Участник 2**. Контракт согласуют все трое.
Ответственный за общий показ — **Участник 3**; каждый демонстрирует и проверяет свою часть.
План предполагает трёх подготовленных участников и доступность необходимых исходных данных. Это оценка объёма одного проекта, не обещание достижения региональных KPI за несколько дней.

## Данные и готовность
Не загружать в Git реальные обращения, персональные сведения, исходные видео, ключи API и пароли. Использовать помеченные тестовые данные и примеры без чувствительных сведений.
Готовность ограничена локальным MVP и проверками, указанными в отчёте. Демонстрационные учётные записи предназначены для локального запуска; production-развёртывание требует отдельной настройки.

Источник постановки — таблица задач GTON, предоставленная пользователем, и согласованное в чатах описание. [Страница программы](https://astanahub.com/ru/l/GTON).
